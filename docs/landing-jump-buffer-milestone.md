## Behavior

A fresh normal jump press received while airborne may remain available for 100 ms from its first authoritative receipt. Its deadline is inclusive in the actual stored binary clock. It launches at the existing pre-KCC jump site, after a real preceding grounded commit. It cannot create a second aerial launch or a same-step post-contact launch. Duplicate messages do not refresh the deadline; the first retained press wins. Normal grounded jumps keep the original chassis/form velocities and behavior.

The client still acknowledges consumption immediately. The retained decision stays private to the authority. Same-life cancellation can clear it after acknowledgment, including stale/equal sequence messages. Climb/contact, form transition/intent, strike request, death/life retirement, stale input and extraction retire it. Bots and the input protocol are unchanged. No render, rig, asset, gravity, speed, collider or physics-version change occurs.

## Observer corrections and evidence limits

Published 20 Hz snapshots can omit a one-tick landing commit. Initial observers also retained missed scheduling windows, normal enemy/life changes and an overlong callsign setup failure. All failed attempts and successor tools remain preserved.

The final diagnostic resolves only the exact private runtime or exact server room. A one-shot ordinary timer moves the actual plain actor/input/retention read after the synchronous game-step task returns. It does not call physics/controller/body queries or change gameplay state. Source call-site hashes, timer clocks, exact identity/life checks, missed ticks, screenshots and terminal outcomes are retained. A timer cannot guarantee every simulation tick will be observed.

Positive cases require live retention, actual airborne processing, an observed grounded commit, a later second launch within the first-receipt deadline and a final grounded state. Expired cases require null retention after that deadline before landing and no second launch. Cancellation separately requires the actual client airborne acknowledgment before a real HUD pause, accepted same-life cancellation and within-deadline null retention. A clear observed at the first grounded commit requires a same/consecutive last-live tick with no gap, before the next possible launch site. Screenshot scope covers airborne bookends and recorded states; it does not certify an uninterrupted interval, wholly rising screenshot or atomic pixel/native timing.
