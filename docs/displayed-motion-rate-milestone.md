# Displayed mech motion rate correction

Private iteration dated 2026-10-05 local time, with execution receipts dated 2026-10-06 UTC. The public friend build remains unchanged. The independent critic approved the bounded displayed gait/turn rate correction and representative rendered-contact aspect; formal release approval remains separate and pending.

## Problem and change

Actors retained the full display interval, then capped cosmetic integration at 50 ms. Linear travel and turn weights nevertheless divided the actual displayed segment by that capped interval. The retained native-history replay shows unsaturated targets inflated by 2× at 100 ms and 6× at 300 ms. These are actual segments returned by the existing render timeline, not assumed native speed multiplied by a frame interval. The 25 m/s target cap limits some larger discrepancies.

`Actors.tsx` now measures linear travel over the full elapsed display interval and passes that interval to quadruped turning and upright motion. `felineMotion.ts` accepts it separately from cosmetic integration. The existing 1 ms denominator floor, 25 m/s linear cap and cosmetic easing remain. Invalid or negative distance and nonpositive/nonfinite elapsed time produce a zero rate target. Angular distance still advances its existing distance-owned cycle; invalid angular measurements produce zero travel.

The native movement, root assignment, timeline, physics, rigs, GLBs, contact gates and chassis stride/duty profiles are unchanged. Optional elapsed arguments default to the existing helper interval. Finite positive intervals through 50 ms retain the former outputs. Upright walk/stride weights deliberately differ on slower frames, which can also change the blend-dependent distance phase and paw support. This does not establish improved authored animation or eliminate every cause of clunky movement.
