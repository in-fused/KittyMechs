## One architecture: versioned floor-datum occupancy profile

Introduce one shared immutable `PhysicalActorProfile`, selected by explicit asset/profile revision, rather than silently changing `ACTOR_HEIGHT` or every chassis radius. It owns: unit/basis/asset hash; carrier-to-floor datum; source/GLTF bind root matrices and separate mount; named articulated chains; five-pad facets; conservative stance/transition occupancy; and compatible pair contact sets. Existing legacy profile IDs stay intact and selectable. The new profile is experimental until qualified; missing/mismatched revision is rejected before creating actor physics or accepting a snapshot.

For the new Pounce, use **one floor-based, yaw-oriented cuboid KCC occupancy hull** derived from the envelope of admitted tail-excluded poses. It is a conservative gameplay body enclosure, not exact skin collision or mass distribution. This avoids claiming that a 3.5m-diameter circular cage is the measured 1.19m-wide animal. Retain the existing native KCC skin/step/slope/gravity behavior initially; changing those is a separate physically observed issue. The profile records outer min/max and local center, including longitudinal asymmetry; server movement, hit queries, guest proxies, camera aim intersection, navigation, spawn/respawn, roof fit and climb clearance consume this same descriptor. Do not shrink an enclosure by subtracting a rounding radius and claim the original box is still covered.

The sampled quad box center is (.00128,.82105,.14485), half extents (.59455,.82105,1.33371); sampled upright center is (.00114,1.26515,−.21695), half extents (.59260,1.26515,1.08940). These are **measurement examples, not proposed shipping constants**: the admitted envelope must contain the actual permitted motion family. No automatic collider resizing per rendered frame. R begins only after admission of the complete intervening occupancy envelope; retraction retains the previously admitted larger envelope until safe completion. Input cancellation changes the planned path, not the floor datum or collider through an obstacle.

Yaw-oriented geometry requires actual angular-path clearance. A fixed-rotation translational shape cast does not prove a turn. Initially the authority can reject blocked turning through a conservative circumscribed turn enclosure around the same floor pivot; it must not rotate the body through cover just because endpoint queries are empty. Ordinary open-space turning should remain responsive. Native angular clearance and cuboid KCC corner/step behavior are unknown until the bounded native case; this proposal does not assert that current helpers already implement them.

Keep actor network `position` as the existing carrier convention initially: floor datum is `position.y−1`, and render root is that datum plus the measured bind/mount relation. `ACTOR_HEIGHT=1` currently defines a reference offset, not the new body's measured half-height: native legacy quad height is2.6 and its collider center is .3 above the body origin. Source004 rest rig object already has Z=−.018 (−.0144m after B); the actual exported node/root relation owns that offset. Do not apply it again, translate every bone by carrier, or align ears to legacy3.8m. One carrier transform is applied once; local skeletal matrices use their actual GLTF/rest basis. The separate legacy actor pi mount must be explicit in the asset profile, never hidden in limb vectors.

## Four chassis and contact/pair compatibility

Asset profile owns semantic roles, not a required bone count: this Pounce forelegs use upper→lower→paw (native link lengths .622151/.714378m); hindlegs use upper→lower→hock→paw (.540992/.705906/.244360m before paw/digits). The hind solver must be a declared three-link strategy, not a renamed two-link solver that omits the hock. Bastion/Lynx/Caracal receive their own measured rig, mass/gameplay parameters, contact facets and occupancy profiles. No new Pounce measurements are multiplied into them or inferred from chassis names. Unsupported combinations retain ordinary attacks/legacy release behavior, without fake pair/animation aliases.

Current `pairCapability` admits Pounce/Pounce same-stance at3.5±.06m, Pounce/Scout quad at3.2m; `createPair` requires actual admitted swept contact and grounded victim, retains both accepted roots, and `advancePair` maintains reciprocal life/phase/escape/cancellation. Those are legacy v3 contact sets, not source004 compatibility. At3.5m face-to-face, the selected quad head-front extents alone leave ~.5429m gap; the selected attacker forelimb-front bound1.45058 plus selected quad core-front1.02118 leave ~1.0282m to a core at the other root. These are oriented AABB comparisons, not an actual claw/body intersection test or proof that every alternative posture is impossible. Source004's isolated role poses were not evaluated together at the accepted roots and cannot replace v3's qualified fallback.

Add pair-contact sets keyed by both physical/rig profile revisions, both stance families and role phases. A set owns root-relative contact targets and support requirements, with actual attacker/victim pose geometry tested together at their accepted roots and phase clock. Any smaller feasible contact separation must emerge from native swept arrival of the real hulls and supported source poses, not `pairSpacing` tuning or repositioning either participant. If the new hull/contact set cannot admit that arrival without overlap, retain normal strike impact/recovery and leave paired pin unsupported. Actual torso yielding, attacker support/claw purchase, victim escape and release recovery are required observations; clip names and reciprocal metadata are insufficient.

## Single target/reference-frame owner, including down/death

Every limb target is explicitly one of `support-local(owner,revision,facet)`, `body-local(bone/profile)` or a current committed free-swing target. The same full-body owner first plans root/core/head and all limb lifecycle states, transports targets into one current armature frame, then checks fixed-link reach/whole-body occupancy/support before committing the complete pose. Body-local guard stays hip-relative during upright death preparation; it is not overwritten by a rest-floor ankle merely because the action label changed. To acquire a floor/down target, release or transfer actual load, lower/rotate the body along a supported admissible path, then replant reachable feet. A rejected plan preserves the preceding complete pose and emits its new request clock separately. No per-limb commit, stretching, hidden IK clamp or instant root shift repairs an impossible request.

Pair targets use the counterpart's **committed** body/contact frame plus profile/life/pair identity; support targets use their actual owner/revision and current pose. Support wake/retirement invalidates the lease immediately and enters supported recovery/rejection. Down/death may relinquish contact authority to a declared native body policy later, but animation does not invent falling/support or move the accepted actor. The source004 failure is a concrete violation of target ownership between upright core and a newly imposed rest-floor foot, not a reason to relax reach.

## Minimal implementation and useful acceptance

1. Add shared profile registry/resolver and strict versioned actor profile identity. Refactor existing config height/radius shortcuts and query/spawn/climb/pair consumers to obtain the same authoritative shape/pivot; guest creates proxies only from that admitted descriptor. Snapshot admission rejects forged profile/shape/pivot and invalid reciprocal pair capability. Default legacy profiles remain unchanged.
2. Bind the new57 rig through measured exported frames/actual pad facets, one pose writer and explicit three-link hind solve. New profile stays opt-in. Before admission, qualify actual floor spawn, both stance motion/turn/stop/jump/land and moving R/reversal under a low ceiling and near a wall; check hull, skin/paws and guest same-clock state together. A blocked control remains blocked. Verify .20m step and real roof edge/full footprint using native owners, not ground rays alone.
3. Ordinary two-client camera evidence should show planted quad gait, purposeful upright stride/guard, no pivot pop on R/cancel, readable wall/roof support, meaningful cover clearance, and source silhouette matching collision/hit expectations. Pair evidence must show actual arrival/impact, both roles' supported pin, claw contact, counter/escape and interruption/recovery against a third actor/obstacle. Measure representative native cost after geometry behavior passes. No collider/body-size waiver is approved here.

Full-frame motion envelope, exact native yaw sweeps, contact-backed cancellation/down/death, paired role retarget/contact, body mass/COM, all four new chassis, native/profile migration and ordinary play remain unknown. No additional source/native/compiler/Blender/browser job was run for this proposal.
