Concrete redundant work: both `overhaulIdentityArt.tsx` and `rainlineExtractionArt.tsx` create visible BatchedMesh containers with `frustumCulled=false` and `perObjectFrustumCulled=true`. An empty ruin batch therefore still reaches renderer culling/list preparation, even though it contributes no triangles. `cityFractureRenderer.ts` already uses the appropriate container-level `visible=count>0` policy.

Proposed ONE candidate, owned paths: `src/game/world/overhaulIdentityArt.tsx` and `src/game/world/rainlineExtractionArt.tsx`. In the existing presentation loop, count exactly the instances whose existing intact/ruin predicate is true and set `group.mesh.visible=count>0` after that group. Initialize each container invisible until its layout presentation apply completes. Preserve every predicate, instance matrix/color, material, geometry, shadow flag and per-instance frustum culling. No new frame callback, React state, asset, physics or limb changes. Reappearance uses the existing discrete presentation subscription, including registered initial state and ruin birth/removal.

Expected effect is skipping empty batches in ordinary and shadow renderer traversal. This cannot be assigned the full 611 ms sampled cost: occupied batches still pay the same culling cost. It does not qualify actual IAB lag or promise a frame rate.
