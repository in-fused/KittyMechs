# Packaged gameplay smoke implementation status

The independently reviewed driver is integrated in `Source/KittyMech/Public/KMGameplaySmokeSubsystem.h` and `Source/KittyMech/Private/KMGameplaySmokeSubsystem.cpp`; matching staging copies remain in `Tools/RuntimeTests`. It has not yet been natively compiled or executed. The existing packaged executable does not acquire this capability until the new source is built and packaged.

`ApplicationCore` is now in the module's private dependencies for the installed input-device mapper. No controller edits were required: viewport input delegates detect physical input, while the driver injects events directly into the existing controller input API. No production combat, AI, movement, objective or recovery implementation is changed.

Scenario `lower-pounce-v1` uses outcome-gated immediate transitions with the plan's absolute deadlines. The parent approved this refinement: waiting idly at a live relay guard after a successful phase can create an unintended early wipe. Required actions now progress immediately after proof, and the fixed lower patrol repeats until second 175. The final five-second idle period remains in the full 180-second native capture. Every phase timestamp, waypoint and completed patrol loop is recorded; comparisons must use the same policy/version and inspect actual workload differences.

The driver creates a GameInstance subsystem only with `-KMGameplaySmoke` in non-Shipping. Pre-map checks require Development configuration, a strict command-line allowlist with no map/URL/ExecCmds/travel arguments, physical fresh user/save directories and no existing checkpoint. The runner fixes the workspace evidence parent. Because a packaged executable's ProjectDir points into its package, native checks require the canonical expected-root parent suffix `/Artifacts/Validation/GameplaySmoke` and exact user/save directory matching rather than incorrectly deriving a workspace directory from ProjectDir. Invalid opt-in preflight exits this dedicated test process synchronously before real map startup.

Mapped key presses/releases and MouseX/Y events pass through `APlayerController::InputKey(FInputKeyEventArgs::CreateSimulated(...))`. All held keys are released at phase transitions and failure. The actual controller mapping must close the menu, move/aim, activate abilities, fire, shield, interact and retry. There is no direct movement/rotation setter, damage application, ability activation, objective completion, enemy suppression/spawn or checkpoint reset call in this driver.

The shield observation records its baseline immediately before a hit and requires one actual damage event with 2.1 ± 0.15 health loss and at least 4.8 energy loss, matching the real skirmisher's 14-damage shot with 85% directional mitigation and a 4.9-energy hit charge (ongoing shield drain may add to energy loss). Signature evidence requires its public zero-cost mobility availability, then an actual follow-up leap with before/after energy observations within 0.5 simulation seconds and no measurable energy debit. An ambiguous long observation interval fails this behavioral assertion; those frames are not removed from the retained failed CSV.

Native CSV capture starts before first actions, anchored by `OnCSVProfileFirstFrame`. Each actual profiler end-frame callback writes the native capture index as `KMSmokeFrame`; these are frame identifiers, not fabricated frame timings. `EndCapture` is polled to file completion before normal exit. The converter follows the installed UE5.8 `FCsvStreamWriter` format: initial header, data rows that may grow as columns appear, final complete header, and bracketed metadata pairs. It requires exact positive finite `FrameTime` values in milliseconds, contiguous indices starting at zero, receipt callback/last-index agreement, and wall-duration agreement within an explicit boundary-frame allowance. Every native data row is retained in the normalized export and aggregate, including idle, first-action and screenshot overhead.

The launcher binds the packaged Windows tree's executable/DLL/cooked-content/config hashes, records hardware/driver/power data and arguments, creates a fresh sandbox, launches only the actual packaged binary, and bounds the process at 300 seconds by default. It retains failures and never rebuilds, repackages, installs software, clears caches or deletes player saves. The validator checks all required outcomes and mapped key press/release records, two actual checkpoint-restored notifications, complete 180-second evidence and ten ordered milestone PNGs. PNG verification checks every chunk CRC and the complete decoded deflate scanlines; visual quality still requires image inspection.

Executed lightweight checks: PowerShell launcher parsing, Python compilation and seven synthetic regression tests in `Tools/tests/test_gameplay_evidence.py`. These cover an exact 10,800-row synthetic bundle, native missing-footer/frame/index/non-finite rejection, PNG truncation/CRC/dimension rejection and missing natural-wipe evidence. They prove validator behavior only. No hardware frame-rate, gameplay action, rendered quality or packaged runtime pass follows from these synthetic cases.
